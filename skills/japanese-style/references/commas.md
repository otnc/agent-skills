# 読点「、」の使い方

回答、進捗報告、手順書、コードコメントなどでは、読み手が語のつながりや文の区切りを一度で捉えられる位置に読点を打つ。会話の相づちや創作の地の文では、間やリズムにも使える。引用、画面のラベル、コードの表記は原文を保つ。

## 外して読めるところ

- 短い主語や話題、目的語、副詞の直後には、そこを区切る理由があるときに打つ。「は」「が」「を」や、文頭の接続詞を見つけるたびに打つと、短い文も細切れになる。長い話題や、接続詞のあとで前後の文の関係が読み取りやすくなる場合は残してよい。
- 直後の名詞を修飾する語、発言や判断の内容を受ける「と」、「〜してください」のような一続きの表現は、途中を区切ると語のつながりが見えにくくなる。短い副詞も、どの動作にかかるか迷わなければ動詞と続けて書く。
- 段落を通して「この変更では、」「また、」「一方、」のような始まりが続くときは、一文ずつ前の文との関係を確かめる。項目を一つ足すだけなら「〜も」でつなげることがある。文頭から短い間隔で読点が続く文は、不要な区切りを一つずつ外して読む。

| 見直す文 | 修正例 |
| --- | --- |
| この設定は、いつでも変更できます。 | この設定はいつでも変更できます。 |
| 先に、トークンを、確認してください。 | 先にトークンを確認してください。 |
| 保存した、ログを確認します。 | 保存したログを確認します。 |
| 更新後は再起動が必要だと、判断しました。 | 更新後は再起動が必要だと判断しました。 |
| 変更内容を確認して、ください。 | 変更内容を確認してください。 |
| ログを確認しました。また、設定ファイルを確認しました。 | ログを確認しました。設定ファイルも確認しました。 |
| この関数は、設定が空のとき、既定値を、返します。 | 設定が空の場合は、この関数が既定値を返します。 |
| この変更では、保存前に、入力値を、検証します。検証に失敗したら、すぐに、エラーを表示します。 | この変更では保存前に入力値を検証します。検証に失敗した場合は、すぐにエラーを表示します。 |
| 指定した保存先に書き込めない場合は、一時ディレクトリに切り替え、ログに警告を出してから、もう一度書き込みます。 | 指定した保存先に書き込めない場合は、一時ディレクトリに切り替えます。警告をログに出してから書き込みをやり直します。 |

## 区切りを示したいところ

- 長い条件や前提が終わる場所は、読点を置くと文の骨組みを追いやすい。「保存先を指定しなかった場合は、設定ファイルと同じディレクトリにログを書き込みます。」のように、条件と操作の境目を示す。「必要なら再試行します。」のような短い条件は続けて読める。
- 動作主が変わる節や対比する節は、境目に読点を置ける。「テストは通ったが、本番ではリクエストが失敗した。」では「が」が二つの節をつないでいる。「テストが通った。」の「が」は「テスト」と「通った」をつなぐため、一続きに書ける。
- 「日時、担当者、連絡先を記録します。」のように、並列する語句の切れ目を示す。項目が長くなる場合は、箇条書きにすると区切りと項目名が見つけやすい。
- 複数の係り先が考えられるときや、同じ種類の文字が続いて語の境目が紛らわしいときは、読点を使える。「担当者は急いで、設定を変更した利用者に連絡した。」では「急いで」が連絡にかかる。なお迷いそうなら「設定を変更した利用者に担当者が急いで連絡した。」と語順で明示する。
- 文頭の接続詞のあとには、文全体の関係を示す区切りが自然な場合がある。「ただし、オフラインでは検索できません。」の読点は例外を示す接続詞の境目にある。一方「次回はまた設定を確認します。」の「また」は「もう一度」の意味で「確認します」にかかる。
- 会話では「うん、見てみるね。」のように、相づちとその先の発言を分ける読点が自然なこともある。

## 語順や見出しを直すところ

- 読点の位置で修飾先が決まる文は、かかる語を近くに置けるか試す。「昨日編集した設定をステージング環境で読み込んだ」なら編集した時点が分かる。「編集した設定をステージング環境で昨日読み込んだ」なら読み込んだ時点が分かる。
- 長い条件、短い副詞、目的語が同じ動詞にかかる文では、長い条件を先に出し、短い語句を動詞の近くにまとめると必要な読点が見えやすい。「すぐに、保存後にプレビューが表示されなかった場合は、ページを再読み込みします。」は「保存後にプレビューが表示されなかった場合は、すぐにページを再読み込みします。」と書ける。
- 手順の見出しで「設定を、保存する」のような型が続くなら、「設定を保存する」のように操作をそのまま示す。「原因は、設定の未保存。」のような見出しは、本文から確認できる結果に合わせて「保存前の変更は反映されない」と書ける。話題だけを案内する見出しなら「設定の保存と反映」のような名詞句も使える。

## 読み直しの手順

1. まず、読点の前後が条件と結果なのか、並列する項目なのか、つながった語句なのかを確かめる。
2. 外した文を読み、意味、修飾先、強調の位置が保たれているかを比べる。読み違えそうなら残すか語順を直す。
3. 数が多くて読みづらい場合は、文や項目の組み立てまで見直す。近くに並ぶ見出しや文の冒頭にも目を通す。読点の個数や同じ位置での繰り返しは見直す目安として使い、位置の適否は文ごとに判断する。

読点が3つ以上ある文は、条件節や列挙などの大きな区切りを先に見つけ、その前後にある短い区切りを見直す。40字を超えて読点が一つもない文では、係り先が一度で分かるか確かめる。短い文でも誤読を防ぐ読点は残し、長い文でも語のつながりが明確なら続けて書ける。

## 根拠と事例

- 国立国語研究所の解説は、文の途中の区切り、修飾関係、並列、語の切れ目を示す例を挙げている。文化庁の公用文の手引も、読点の位置で意味が変わる例や、語順を変えて読みやすくする考え方を示している。[国立国語研究所の読点の解説](https://kotoba.ninjal.ac.jp/qa/yokuaru/qa-53/)、[文化庁の公用文作成の考え方](https://www.bunka.go.jp/seisaku/bunkashingikai/kokugo/hokoku/93657201.html)
- 日本語の両義文を使った読文実験では、意味に沿った位置に読点を打つと、その語を読む時間は長くなり、その先で曖昧さを解消する箇所の読み時間は短くなった。[新国・邑本の読文実験](https://www.jstage.jst.go.jp/article/jjpsy/85/2/85_85.13311/_article/-char/ja/)
- 人文系論文60本を調べた研究では「は」の直後に読点が打たれた割合は4割弱で、文の長さや段落での位置などによって打たれやすさが違った。接続詞についても、語の種類や文章のジャンルで傾向が異なる。[「は」直後の読点を調べた研究](https://www.jstage.jst.go.jp/article/jtje/26/0/26_27/_article/-char/ja/)、[接続詞の直後に読点が打たれる要因](https://www.jstage.jst.go.jp/article/mathling/31/6/31_426/_article/-char/ja/)、[岩崎拓也『現代日本語における句読点の研究』](https://cocopb.com/books/978-4-86676-062-9/)
- 修飾語と述語の位置を変える方法は、作文の指南書や技術文書を書いた人の実例にもある。講演を文字にしたような長文は、読点を足す前に動作主と動作を近づけ、必要なら文を分けるとよい。[本多勝一『〈新版〉日本語の作文技術』](https://publications.asahi.com/product/17593.html)、[Qiita の語順の修正例](https://qiita.com/Gaakuu/items/36a70ab00d8a3347c750)、[Qiita の技術記事の書き方の実例](https://qiita.com/Yametaro/items/21b8772e6c0d1d77e176)
- AI の下書きを推敲した Zenn の事例では、文を短く組み直して不要な読点を減らした箇所もある。別の技術記事の試行では、文章校正ツールが指摘した読みづらさの修正に前後の意味を判断する作業が残った。[Zenn の業務報告の推敲例](https://zenn.dev/koji4/articles/42b8c6d5901323)、[Zenn の AI 生成文の校正実験](https://zenn.dev/numarn/articles/japanese-doc-lint-handson)
- 広島大学の卒業論文では、比較した二つの題材で全体として AI 生成文のほうが読点が多かった。Zenn の比較では、AI が書いた実用文17本を推敲し、15本で読点が減った。Qiita には文中の読点数を確認する textlint の設定例がある。[大西夢の卒業論文](https://home.hiroshima-u.ac.jp/jshira/papers/AI%E7%94%9F%E6%88%90%E6%96%87%E3%81%8B%E3%82%89%E3%81%BF%E3%81%9F%E3%80%8C%E8%87%AA%E7%84%B6%E3%81%AA%E6%97%A5%E6%9C%AC%E8%AA%9E%E3%80%8D%E3%81%AB%E3%81%A4%E3%81%84%E3%81%A6%E3%81%AE%E7%A0%94%E7%A9%B6%EF%BC%88%E5%A4%A7%E8%A5%BF%E5%A4%A2%EF%BC%89.pdf)、[Zenn の推敲前後の比較](https://zenn.dev/kakushigoto/articles/slop-banlist-vs-yomiyasu)、[Qiita の textlint 設定例](https://qiita.com/k8uwall/items/3c29ef2dce153e13bd1d)
