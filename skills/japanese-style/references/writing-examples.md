# 日本語の修正例

## 会話と進捗報告

想定する場面は、日本語のやり取りの途中で、CI が `Error: Missing environment variable API_URL` を返したとき。

- 修正前「The CI job failed because API_URL is missing.」
- 修正後「CI は `API_URL` が未設定で止まったよ。ログには `Error: Missing environment variable API_URL` と出ている。」

原因の説明は会話の言語に合わせる。ログは、読み手が同じエラーを検索できるよう原文を引用する。

## ドキュメント

既存の README が「です・ます」調で、同じ処理を「リクエスト」と呼んでいる場面。

- 修正前「要求の送信前に、設定値の確認を行う。」
- 修正後「リクエストを送る前に、設定値を確認します。」

文末と用語は周囲の文章に合わせる。「確認を行う」は「確認する」で動作が伝わる。

## コードコメント

同じ ID に対する重複処理を防ぐため、リクエストを送る前に処理済みの ID を確認する場面。

- 修正前「処理済みの ID を確認する。」
- 修正後「リトライ時に同じ ID のリクエストを二重送信しないため、処理済みか確認する。」

処理の理由がコードだけでは読み取りづらい場合は、どの条件で何を防ぐのかを書く。

## 結論と要約

手元で障害を再現しようとしたが再現せず、修正は入れていない場面。

- 修正前「不具合は解消しました。」
- 修正後「手元の環境では不具合を再現できませんでした。」

要約では、確認した環境と結果が伝わるように書く。
