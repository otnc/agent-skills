# LLM が書きやすい日本語の癖

LLM の下書きを見直すときと LLM として回答を書き終えたときに確かめる項目。ここに挙げた言い回しは人間も使う。言い回しが見つかっても直すかどうかは文ごとに決め、その文が読み手に何を伝えるかで判断する。

## 決まった前置きと結び

モデルごとに決まった言い回しで回答を始めたり終えたりする癖がある。どれも読み手に新しい情報を渡さない。

- 「以下の通りです：」「主な理由は以下の通りです：」のような導入だけの文を置かず、最初の文で答える。リストの前に枠を示す文が要るときは「理由は2つある。」のように数や対象を書く。
- 「結論から申し上げますと」「解説します」のような予告を書かず、結論そのものを書く。
- 「具体的に知りたいことはありますか？」「お気軽にお尋ねください」「ぜひ試してみてください」で終えない。作業を進めるのに必要な質問だけを書く。

## そろいすぎた形

- 文の長さがそろい、どの段落も同じ文数で終わる文章は内容より形が目立つ。段落の文数は書く内容の数で決め、文数をそろえるために文を足したり削ったりしない。
- 短い回答にも見出しと箇条書きを付ける癖がある。見出しは読み手が探す単位があるときだけ付ける。原因と結果のつながりは箇条書きにせず文で書く。
- 節ごとに「まとめ」の文を置かない。最後の段落には本文にない次の操作か示唆を1つだけ書き、なければ最後の根拠の文で終える。

## 打ち消しの多用

「AではなくB」「単なるAではなく」の形は読み手が実際にAと考えていそうなときだけ使う。そう考えていなさそうなときはBだけを書く。

- 修正前「このスクリプトは手作業ではなく自動で実行されます。」
- 修正後「このスクリプトは毎日9時に自動で実行されます。」

## 論文調の述語

「〜を示している」「〜を示唆している」「〜を意味している」「〜ことが知られている」「〜点に留意が必要である」は誰が何を確かめたのかを消す。データの話なら何を比べて何が分かったかを書き、確かさに合う文末を選ぶ。数値は元の資料や測定結果にあるものだけを書く。

- 修正前「この結果はキャッシュの有効性を示唆している。」
- 修正後「キャッシュを有効にすると応答時間の中央値が下がった。下がった量はまだ測っていない。」

## 英語の構文と語彙の写し

- 英語の関係詞節を「それが〜につながる」「これにより〜」でつなぐ形は日本語では回りくどい。「自動車の所有が増え、それが事故の増加につながる。」は「自動車が普及して事故が増える。」と書ける。
- 英単語を辞書の訳語に置き換えると組み合わせがずれる。solve の訳の「コストを解消する」は「コストを削減する」、dispatch の訳の「ジョブの搬送」は「ジョブの配信」と書く。名詞と動詞の組み合わせを普段の会話で言うかで確かめる。
- 「確認を行う」「〜することができます」「〜となります」は動作を名詞や補助的な語で包む。「確認する」「〜できます」「〜です」で意味が変わらないなら短いほうを使う。

## 前後の内容の食い違い

長い文章では前に書いた内容と後の内容が食い違ったり、接続語が前後の関係と合わなかったりする。「そのため」「すると」「その結果」の前後に原因と結果があるかを確かめる。登場した人物、設定、数値、用語が途中で変わっていないかも確かめる。

## 見直しの手順

1. 冒頭と末尾の文だけを読み、決まった前置きと申し出を消す。
2. 段落ごとの文数と見出しの数を数え、内容より形がそろっていないかを見る。
3. 「ではなく」「示している」「示唆」「つながる」「以下の通り」を検索し、1つずつ文の役割を確かめる。
4. 接続語の前後で因果が成り立つかを読む。
