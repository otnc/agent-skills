# agent-skills

**English** | [日本語](README.ja.md)

A generated aggregation of otnc's `skills_*` agent-skill repositories: every skill published there becomes installable from this single source with the [skills CLI](https://github.com/vercel-labs/skills).

> [!NOTE]
> `skills/`, `sync-state.json` and the skill list sections of the base documents are generated by `cmd/sync`. Do not edit them here; changes belong in the source repositories listed below.

## Install

```bash
# List every skill in this repository
npx skills add otnc/agent-skills --list

# Install a specific skill
npx skills add otnc/agent-skills@fix-unnatural-line-breaks

# Install to specific agents
npx skills add otnc/agent-skills@token-saver -a claude-code -a codex
```

## Past versions

Every synced release is tagged `<repository>@<tag>` (for example `skills_fix-unnatural-line-breaks@v0.4.0`), so past versions remain installable from this repository:

```bash
npx skills add https://github.com/otnc/agent-skills/tree/skills_fix-unnatural-line-breaks@v0.4.0
```

## How this repository stays current

A scheduled workflow runs twice a day (10:30 and 22:30 JST) and can also be triggered on demand. It automatically discovers new public `otnc/skills_*` repositories. A repository is picked up only when it passes all of these checks:

- **Public** — private repositories are never vendored in.
- **Really a skills repository** — it contains a `SKILL.md`, either at the root or directly under `skills/`.
- **Released** — it has at least one published (non-draft, non-prerelease) GitHub release.

Repositories to skip can be listed in [`sources.json`](sources.json). The skill list above and the source list in [CONTRIBUTING.md](CONTRIBUTING.md) are regenerated by every sync run. To add a new skill repository, see [CONTRIBUTING.md](CONTRIBUTING.md).

## Issues and pull requests

This repository is generated. Issues and pull requests about a skill's content belong in its [source repository](#included-skills) — anything merged here would be overwritten by the next sync. Open an issue or pull request here only when the sync machinery itself (`cmd/sync`, the workflow, the generated docs) is broken or buggy.
