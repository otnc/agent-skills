## Adding a new skill repository

1. Create a public repository named `skills_<something>` under `otnc` with your skill at `skills/<name>/SKILL.md` (a root-level `SKILL.md` also works).
2. Publish a release (for example `v0.1.0`). Draft and prerelease releases do not count.
3. Wait for the next sync run (twice a day), or trigger it immediately:

   ```bash
   gh api repos/otnc/agent-skills/dispatches -f event_type=sync
   ```

The sync validates every candidate: it must be public, not a fork, not archived, contain a `SKILL.md` (at the root or directly under `skills/`), and have at least one published release. Repositories that fail validation are skipped and reported in the workflow log. Once synced, the skill list in the README and the source list above are regenerated automatically.

To exclude a repository permanently, add it to `exclude` in [`sources.json`](sources.json).

## Agent skills

AI coding agents get extra instructions ("skills") from [`.agents/skills/`](.agents/skills/) via the [`skills` CLI](https://www.npmjs.com/package/skills) (`npx skills`). Only `.agents/skills/` and [`skills-lock.json`](skills-lock.json) are committed — that's the canonical copy. Every other location a given agent might look in (`.claude/skills/`, `agent/skills/`, ...) is a generated symlink or copy and is gitignored; recreate them after cloning with:

```sh
npx skills experimental_install
```

The installed skill ([kiritan](.agents/skills/kiritan/SKILL.md)) teaches an agent how to work with the Kiritan i18n setup this repository uses. Load it before editing anything under `base/`.

## Running the sync locally

```bash
go run ./cmd/sync --dry-run   # plan only, no changes
go run ./cmd/sync             # apply, commit and tag locally
go run ./cmd/sync --replay    # first-time setup: rebuild history from all past releases
```

`GITHUB_TOKEN`/`GH_TOKEN` is optional for public repositories but avoids rate limits. Commits are authored with `SYNC_GIT_NAME`/`SYNC_GIT_EMAIL` when set (the workflow sets them to `github-actions[bot]`), otherwise with the local git config.

## README and CONTRIBUTING

`README.md`, `README.ja.md`, `CONTRIBUTING.md` and `CONTRIBUTING.ja.md` are generated from the files under [`base/`](base/) with [kiritan](https://github.com/otnc/kiritan), which is a devDependency. Edit the base files, then:

```sh
npm install
npm run build      # kiritan build
npm run docs:check # kiritan check: fails if generated docs are stale
```

The skill list sections in `base/README.base.md` and the source list in `base/CONTRIBUTING.base.md` are regenerated by the sync itself — do not edit those sections by hand.
